## Display contract

**Scaled Fit** requests a fraction of the panel's physical pixel dimensions
(default 1/2), then fits that desktop locally into the panel. Presets are 1/4,
1/3, 1/2, 2/3, 3/4, and 1/1. Ratios are stored as numerator/denominator and used
directly in integer arithmetic: 2/3 of 3840 x 2160 is exactly 2560 x 1440.
Existing percentage-only profiles remain readable. As clarified by
the user during live testing, window resizing must update the remote resolution,
preserving the lower pixel density: 3840 x 2160 maps to 1920 x 1080, and
2560 x 1440 maps to 1280 x 720. Updates are debounced by 300 ms and deduplicated.
Focus Mode changes and active-tab layout changes use the same policy. The client
sets `EnableZoom=true` before connection, as SmartSizing alone does not upscale.
**Actual Size** uses a fixed saved remote resolution with scrolling.
**Match Panel** requests a remote resolution matching the panel and permits
debounced dynamic display updates when supported.

Hyper-V basic consoles have guest-controlled resolution. Local fitting still
applies, but the selected resolution is a request, not a guarantee. Enhanced mode
is explicit and requires support on the host/guest. Do not silently fall back.

## First-version layout

Searchable saved connections on the left, a compact command row and session tabs
above the remote surface. Focus Mode hides the sidebar and normal command rows;
a small local exit strip remains accessible even when RDP captures keyboard input.
Full-screen is independent of the display resolution policy.

## Live RDP results

- Windows authentication succeeded on the user-designated RDP host.
- At a 3450 x 1854 panel size, the server reported 1724 x 927. The native rendered
  desktop was 3448 x 1854, confirming local upscaling (small width difference due
  to server rounding and aspect-ratio preservation).
- Resizing the window produced a 2148 x 1184 panel and a 1072 x 592 remote desktop,
  confirming that remote resolution follows the panel at the saved 50% scale.
- The final live Focus Mode check was interrupted by RDP disconnect reason 3:
  another client connected to the same remote session. No competing reconnect
  was attempted. Offline Focus Mode checks passed; live confirmation remains open.
